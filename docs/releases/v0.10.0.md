# AgentFence v0.10.0 — VeriCordon local/CI authorization evidence

This release makes the VeriCordon authorization-evidence experiment available
as a versioned local/CI consumer surface.

**Value proposition:** generate inspectable authorization evidence for the exact
calls and policy AgentFence evaluated.

## Use

```yaml
- uses: dgenio/agentfence/evidence-action@v0.10.0
  with:
    policy: agentfence.yaml
    calls: testdata/tool-calls.jsonl
    tests: testdata/policy-tests.yaml
```

The Action produces human-readable Markdown plus versioned JSON and uploads a
safe aggregate artifact. Raw `audit.jsonl` is excluded from the uploaded
artifact by default.

## What this release can establish

For the evidence supplied to a run, VeriCordon can establish:

- the decisions for supplied calls actually evaluated through the boundary;
- whether the supplied policy validated;
- policy-fixture results when fixtures are supplied;
- whether the supplied local tamper-evident audit chain verifies;
- exact-action + resolved/effective-policy binding for representable evaluated
  calls when the corresponding audit evidence is present;
- the provenance files supporting each reported check, together with explicit
  limitations.

Missing evidence remains `partial` or `not_evaluated`; it is never promoted to
`observed` by absence.

## What this release does not establish

It does **not** establish:

- complete mediation of the agent, framework, host, or tool surface;
- sandboxing;
- prevention of prompt injection;
- downstream execution safety after a call is allowed;
- authenticated human identity unless that identity is actually provided and
  bound by the approval channel;
- compliance certification or conformance with AIUC-1 or another standard;
- correctness or appropriateness of the operator's policy for its environment.

A valid local hash chain detects covered record mutation/reordering under the
verifier contract; it does not prove complete collection or external anchoring.

## Release-gate evidence

The maintained repository gate observes complete action/policy binding for all
representable evaluated calls. A separate fresh-consumer test in an unrelated
repository produced a safe artifact with 3/3 evaluated audit events bound,
3/3 policy fixtures passing, and an intact three-event audit chain. The raw
audit log was not present in the published artifact.

The fresh-repository test also exposed one onboarding defect: a newly introduced
workflow using only `pull_request` does not bootstrap in GitHub Actions. The
public copy/paste workflow now includes an initial `push` trigger as well as
`pull_request`.

## Product boundary

This release intentionally stops at **local/CI authorization evidence**. It does
not add a hosted control plane, hosted gateway, dashboard, account system,
billing, retained history, or enterprise team-management layer.
